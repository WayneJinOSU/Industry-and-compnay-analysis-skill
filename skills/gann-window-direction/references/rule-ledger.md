# 规则演进账本

用途：记录方向判别层的**规则级**变更，确保“复盘 → 泛化”而不是“复盘 → 增加个案分支”。

## 记录格式

| 日期 | 触发案例（仅溯源） | 旧规则 | 新规则（状态量表述） | 适用范围 | 验证方式 |
|---|---|---|---|---|---|

## 条目

### 2026-10-24.6｜中文情景表与双语门禁

- 触发案例（仅溯源）：用户在阅读 2026-10-23 严格回放时指出，英文情景代码
  `key_level_test`、`breakdown_or_breakout` 等较难快速理解；虽然 JSON 需要稳定
  枚举，报告的阅读层不应要求用户在英文代码与中文走势之间手工映射。
- 旧规则：报告门禁要求正文出现四个英文情景名，中文名称只能作为解释；权重
  解析也优先匹配英文代码。
- 新规则：
  1. 中文报告固定使用“趋势延续”“关键位区间测试”“关键位突破/破位”“尾部极值”
     四个标准中文名；
  2. 可在标准中文名后加括号说明路径性格，例如“关键位区间测试（基准：低开
     下探、日内修复）”，但不得用括号说明替代标准名；
  3. JSON、CSV、门禁和评分继续使用原英文机器枚举，不使用中文重命名字段；
  4. 方向门禁同时识别标准中文名与英文机器名，并对两种写法执行相同的权重、
     收盘区间和可判定条件检查。
- 适用范围：所有中文方向报告；其他语言报告按用户语言表达，但机器枚举不变。
- 验证方式：`selftest.py` 新增中文情景表权重解析与门禁通过测试；用中文版
  2026-10-23 情景表回放，四情景、权重、收盘区间、孤立位披露与最终 manifest
  检查均通过。

### 2026-10-24.2｜生产级输出契约与阶段快照（新增）

- 触发案例（仅溯源）：2026-10-16 标准稿虽已正确区分结构、窗口与执行状态，并纳入了日韩澳台开盘价，但存在四个可复现缺陷：四情景权重未精确闭合且收盘区间有缺口/重叠；`external_snapshot` 中的 SOX 未合并进输入包，导致状态量判 `external=uninformative` 而正文仍使用外盘修复叙事；正文缺少完整领涨六项；盘前与另一条流程的盘中/状态文件写在同目录。
- 旧规则：输出标题、field 清单和四情形名称虽有规定，但门禁只检查关键词、权重与大致数值区间；manifest、报告决策卡、外盘记录元数据、领涨字段和阶段目录没有形成完整校验链。
- 新规则：
  1. 完整报告必须以机器可读的决策卡开头，并同时声明 `prediction_type`、`ruleset_version`、`forecast_cutoff`、`target_date` 与四轴状态；
  2. `external_snapshot` 必须先合并到 `direction_input_pack` 再运行状态量；US 锚点须包含 SOX，外盘记录逐项保留 `trade_date/source/available_at`；截止时间落在目标日 08:00 以后时，报告须覆盖日经、KOSPI、澳洲的状态；
  3. `leadership` 必须披露 `leader_ret`、`market_equal_weight_ret`、`leadership_spread`、`gap_up_fade_rate`、`leader_above_rate`、`rebound_quality`，缺失时显式 unknown；
  4. `forecast_record` 必须声明 `close_axis=close`、`interval_convention=lower_inclusive_upper_exclusive`，四情景区间连续、无重叠、权重合计 100%；
  5. 持久化报告按 `premarket/intraday/postclose/backfill` 隔离；采用“无 manifest 预检 → 回写 gate_status → 冻结 → 带 manifest 终检”两阶段门禁，终检必须校验 manifest 元数据和文件哈希。
- 适用范围：所有盘前、盘中、盘后与历史补做输出；临时探索稿可以不带 manifest，但不得称为正式归档输出。
- 验证方式：用 2026-10-16 稿回放，新门禁应捕获缺失的领涨字段、决策卡字段、外盘状态一致性与 manifest；用 2026-10-23 修正稿及重建 manifest 回放，结构、外盘、领涨、四区间和哈希检查应全部通过；再对冻结报告追加一个字节后回放，`snapshot_manifest` 必须因 SHA256 变化而 fail。2026-10-23 与 2026-10-26 两套正式结构回归均已在临时隔离目录通过（仅保留原有缺口 warning）。

### 2026-10-16｜领涨结构门槛与超跌反弹分类（新增）

- 触发案例（仅溯源）：2026-10-16 盘中，指数与全市场等权同步上行（指数 +0.74%、等权 +1.38%、上涨占比 0.82），但审定篮子 16 只等权仅 +0.66%（`leadership_spread = −0.73pp`；AI 算力/半导体子集 12 只更弱，+0.43% / −0.95pp），`leader_above_rate = 0.20`；篮子中开盘缺口 ≥1.5% 的 9 只里有 3 只收于前收盘之下（最大 −3.98%），领涨板块为地产（+5.4%），创业板指 +0.29% 落后国证 2000 +1.09%。当日的盘中复盘把“向上确认情景”写成“正在胜出”，依据只有宽度达标；事后按宽度与领涨结构并列复核，性质应为超跌反弹。
- 旧规则：`leadership` 虽被列为独立证据维度（[evidence-rules.md](evidence-rules.md)），但没有可测量口径、没有阈值，也没有与 `window_state` 升级挂钩；`unresolved → bullish_confirmation` 只要求“市场内部或主线板块没有明显反向拖累”，属缺省式条件；广度改善可被当作向上确认的证据。
- 新规则：
  1. 新增 [evidence-rules.md](evidence-rules.md) 的领涨结构一节：定义 `leader_ret`、`market_equal_weight_ret`、`leadership_spread`、`gap_up_fade_rate`、`leader_above_rate`，并给出 `leadership_confirming / leadership_neutral / leadership_lagging` 的阈值；
  2. `unresolved → bullish_confirmation` 增加**领涨结构确认**为必要条件（四项同时成立，缺一不可）；
  3. 新增 `rebound_quality = leadership_repair | oversold_bounce | unclear`：广度改善 + `leadership_lagging` 判 `oversold_bounce`，不得升级 `window_state`、不得改写 `structural_bias`、不得把“回到中枢”写成基准情景；
  4. 盘中不得宣布情景“胜出”，只能标候选；`intraday_partial` 读数不得与收盘读数混用；
  5. 状态量由 [scripts/leadership_state.py](../scripts/leadership_state.py) 确定性产出，人工不得用叙事替代数值。
- 适用范围：所有标的、所有决策阶段；凡出现“价格反弹但方向未决”的时点均须执行。
- 验证方式：用 2026-10-16 的同一组盘中读数回放——脚本从个股日线 + 全市场宽度算出 `leadership_spread = −0.73pp`、`gap_up_fade_rate = 0.33`、`leader_above_rate = 0.20`、`state = leadership_lagging`、`rebound_quality = oversold_bounce`，据此 `window_state` 保持 `unresolved`，与当日实际（指数收涨但主线高开回落、地产领涨）一致。脚本输出：`outputs/window_direction_20261016/leadership_state_20261016.json`。收盘后须以完整交易日口径复算并更新本条；累积方向正确率与 `in_gap_rate` 仍按 [contract.md](contract.md) 与 `scripts/scorecard.py` 滚动检验。

### 2026-10-15｜信息量门槛、位置身份与状态条件权重（首版）

- 触发案例（仅溯源）：针对 2026-10-14 的预判把约 50% 权重给“回到区间中枢”，当日实际收在振幅下缘；收盘下方六档支撑 `hold_rate` 全为 1.00，但同一交易日被连续击穿三档；驱动当日开盘的外部市场当日几乎走平，却被当作“中性”。
- 旧规则：不区分档位形成窗口，多档未跌破位置被当作支撑厚度；`uninformative` 输入层没有专门判定；情景权重默认 50/25/25 之类固定比例。
- 新规则：见 [evidence-rules.md](evidence-rules.md) 的信息量、位置身份、量级、情景边界与复盘归因条款。
- 适用范围：所有标的、所有决策阶段。
- 验证方式：用修改前的同一组输入回放，确认情景权重与分支集合发生变化 —— 回放记录：2026-10-14 预判的输出目录下 `规则回放检验_20261015.md`。结论：旧情景树在 3741.11–3795 存在 54 点收盘区间空档，实际收盘 3767.23 落入空档；新情景树无空档且落点进入 35% 权重的 `key_level_test` 分支，与 40% 权重的 `trend_continuation` 合计覆盖 75%。同源带机械判据识别出的支撑带（3800.11→3754.14）与实际“内侧三档被逐个击穿、防线守住”的行为一致。后续按 [contract.md](contract.md) 做滚动样本外检验。

### 2026-10-15｜倍数比口径约束（自查修正）

- 触发案例（仅溯源）：对 2026-10-14 的复盘在比较“北向净流入 vs 融资净流出”时，使用了截点之后才出现的 −107 亿，并跨窗口比较，得出“量级差 4 倍以上”的结论。
- 旧规则：只要求“给出量级与倍数比”。
- 新规则：倍数比必须在同一窗口、同一口径、且只用截点前可得数据计算；存量与流量不得直接比大小。见 [evidence-rules.md](evidence-rules.md)。
- 适用范围：所有证据量级比较与冲突判定。
- 验证方式：同一案例重算 —— 同窗口同口径倍数为 1.9 倍（真冲突），原“4 倍”结论撤回并改判归因类型。

### 2026-10-16｜执行层门禁、状态量输入与极值状态（新增）

- 触发案例（仅溯源）：规则更新后连续两份预判（目标日 2026-10-15、2026-10-16）仍使用固定 45/25/25 权重、未逐层给出 `information_content`、未采用四形态情景命名、复盘未按四类归因对账，报告却照常输出三状态结论；2026-10-16 目标日出现向上修复路径，而基准情景仍为“温和下跌”，属把单日极值读数当作持续趋势。
- 旧规则：`evidence-rules.md` 已定义信息量门槛与状态条件权重，但**没有任何机制在字段缺失时使报告失败**；三个状态量与逐层信息量依赖人工判断；极值读数与持续状态未区分。
- 新规则：
  1. 方向层强制执行门禁 `scripts/direction_gate.py`（对应 [SKILL.md](../SKILL.md) 工作流 11）：任一项 fail 时报告头必须标 `gate_status=failed`，且不得输出 `structural_bias / window_state / execution_state`；
  2. 状态量与逐层信息量由 `scripts/state_inputs.py` 确定性产出，人工判断不得替代；
  3. 新增极值状态 `breadth_extreme` / `funding_spike`，反向分支权重下限 25%，且必须附同口径条件分布统计——见 [evidence-rules.md](evidence-rules.md)；
  4. 外部锚点缺失（含 AI 算力链对应的费城半导体 SOX）时该层只能判 `uninformative` 并登记 `data_gap_register`，禁止静默丢弃或把该层标为完整。
- 适用范围：所有标的、所有决策阶段。
- 验证方式：用 2026-10-16 目标日的同一组输入回放 —— `direction_gate.py` 对旧报告输出 `gate_status=failed`（6 项 fail：逐层信息量、四形态情景、缺口登记、复盘归因、rule-ledger、规则版本）；`state_inputs.py` 从同一组输入判出 `weekly_regime=down`、`funding_state=deleveraging`、`breadth_extreme_low=true`、`funding_deleveraging_spike=true`，即极值状态在事前可被识别，而旧流程未生成该字段。回放记录见 `outputs/window_direction_20261016/gate/direction_gate.json` 与 `outputs/window_direction_20261016/state/state_inputs.json`。

### 2026-10-16｜极值状态的条件分布检验，与两条设想的撤回

- 触发案例（仅溯源）：为第 7 节的“反向分支下限 25%”寻找数据依据，同时检验此前口头提出但未验证的两条设想 —— “破位后落在已知锚点并长影回收 → 反弹情景权重上调”“单日大幅去杠杆 = 衰竭 → 次日均值回复”。
- 估计器：`scripts/extreme_state_stats.py`，样本 上证指数 2005-01-04 至 2026-10-14（n=5287），状态用分布尺度定义（60 日 z 分数、20 日 σ），前瞻 T+1/T+3/T+5，单侧二项检验对无条件基线（T+1 上涨概率 53.3%）。
- 检验结果：

| 状态 | 样本 | T+1 上涨概率 | 对基线超额 | p | 裁决 |
|---|---:|---:|---:|---:|---|
| 2σ 单日下跌（crash，全样本） | 168 | 63.1% | +9.8pp | 0.007 | 有超额 |
| 2σ 单日下跌（限下跌趋势内） | 97 | 57.7% | +4.4pp | 0.220 | 无显著超额 |
| 两融去杠杆脉冲（funding_spike） | 490 | 55.9% | +2.6pp | 0.132 | 无显著超额 |
| 两融去杠杆脉冲（限下跌趋势内） | 364 | 54.1% | +0.8pp | 0.397 | 无显著超额 |
| **20 日低点处长下影（shadow_at_low）** | 72 | **47.2%** | **−6.1pp** | 0.875 | **方向相反** |
| 长下影且限下跌趋势内 | 64 | 48.4% | −4.9pp | 0.817 | 方向相反 |
| 跳空低开后收阳（gap_recovery） | 198 | 50.5% | −2.8pp | 0.805 | 无超额 |

- 被替代的旧规则：
  1. 撤回“破位后落在已知锚点 + 长影回收 → 上调反弹分支权重”这条设想 —— 全样本与下跌趋势内样本的 T+1 上涨概率都**低于**基线（47.2% / 48.4%），T+3 均值也为负（−0.25% / −0.32%）。该形态不构成反弹证据，不得写成规则。
  2. 撤回“大幅去杠杆脉冲 = 衰竭 → 次日反转”这条设想 —— 超额 +2.6pp / +0.8pp，均不显著。
- 新规则：第 7 节的 25% 下限**维持不变**；仅当状态为“2σ 单日下跌且不在下跌趋势内”时，才允许把反向分支下限升至 35%（`recommended_reversal_floor` 由脚本逐状态给出）。其余极值状态一律按 25% 处理，且报告中必须写出“该状态无显著超额”。
- 适用范围：所有标的的极值状态权重处理；状态定义与阈值以脚本的分布尺度为准，不得改回固定个案阈值。
- 验证方式：`extreme_state_stats.py` 可在任意标的与任意数据区间上重跑；本次输出 `outputs/extreme_state_stats/extreme_state_stats.csv` 与 `.json`。滚动样本外检验仍按 [contract.md](contract.md) 执行。

### 2026-10-24｜量能压缩语义、外盘分层映射、清算状态与预测出处（新增）

- 触发案例（仅溯源）：
  1. 2026-10-16 至 10-21 连续缩量（成交量 z 分数最低 −1.68），被当作“抛压衰竭”的偏多依据；10-22 转为放量下跌（−1.48%，上涨占比 0.0961、等权 −2.64%、融资净流出 235 亿）。
  2. 10-20 美股期货 +1.2%，A 股实际低开；10-21 日韩跳空 +1.3%~+2.1%，而 A50 期货 0.00%，A 股高开兑现；10-23 日韩低开、A50 仍 0.00%，A 股低开修复。区域涨幅与 A 股开盘方向多次背离。
  3. 10-23 跨资产同跌（纳指 −2.60%、COMEX 黄金 −2.87%），A 股盘中最低 3574.27，击穿全部静态支撑（最外侧 3602.15），收盘回到 3690.48。静态档位无法约束日内极值。
  4. 10-21 与 10-23 的报告为事后补做，当时被写入输出目录，与事前预测混放，存在统计污染风险。
- 旧规则：
  1. 量能只按“放量/缩量”描述，未区分压缩发生在压力位下方还是支撑上方；缩量下跌可被直接称为“抛压衰竭”。
  2. 外部市场按“方向+强度+一致性”整体处理，没有相关性分层；日韩与美股的涨幅可直接影响 A 股开盘先验。
  3. 关键位档位同时被用作收盘目标与日内极值目标。
  4. 记分账本没有 `prediction_type`，补做与事前预测混算。
- 新规则：
  1. 新增 `volume_compression` 状态与 `compression_side`（见 [evidence-rules.md](evidence-rules.md)）：压缩不产生方向；压缩期间 `breakdown_or_breakout` 下限 25%，无宽度/等权修复确认时不得把“回到中枢”作为基准；压力位下方的压缩偏脆弱、支撑上方的压缩偏蓄势，仅作 5–10pp 先验调整。
  2. 外盘映射分层（见 [evidence-rules.md](evidence-rules.md) 的“外部映射”）：`tier_1` 同标的境外代理（A50 期货、中概、恒指）> `tier_2` 区域（日韩台澳）> `tier_3` 全球（美欧）。开盘缺口先验只取 `tier_1`；`tier_1` 与低层级背离时，外部层判 `weak`，不得用低层级定方向；`tier_1` 缺失判 `uninformative` 并登记缺口。
  3. 新增 `cross_asset_liquidation`（驱动股指单日 ≤ −1.5% 且黄金同日 ≤ −1.5%，见 [evidence-rules.md](evidence-rules.md)）：该状态下档位只约束收盘，日内极值允许越过最外侧档位 1.5–2 ATR；目标必须拆成 `close_target` 与 `intraday_extreme_target`，情景需含 `liquidation_flush`。
  4. 预判记录必须带 `prediction_type`（`prospective` / `backfill`）与 `ruleset_version`；`scripts/scorecard.py` 只以 `prospective` 计算方向正确率与最高权重分支命中率，`backfill` 单列。
- 适用范围：所有标的、所有决策阶段；量能、外盘、跨资产与记分账本均为通用层，不绑定具体日期或点位。
- 验证方式：

  2. 日期、时间、规则版本、点位、比例和得分继续使用数字，不改为中文数字；
  3. 结构化记录继续保留稳定机器枚举，门禁负责把中文展示值规范化后校验；
  4. 报告不得再把原始机器字段块作为首要阅读界面。
- 适用范围：所有面向中文用户的盘前、盘中、盘后和历史回放报告。
- 验证方式：新增中文报告头、中文决策卡和中文执行状态规范化测试；用
  2026-09-22 历史回放重新生成中文展示稿，预检、冻结和终检均须通过。

### 2026-10-25.5｜数量数据统一使用阿拉伯数字

- 触发案例（仅溯源）：中文展示稿虽然已把字段和状态翻译成中文，但情景路径、
  目标、失效条件和证据表仍把价格、百分比、日期、周期与金额写成中文数字，降低
  了交易报告的可扫描性和复制精度。
- 旧规则：只要求正文和字段中文化，没有约束数量数据的数字书写形式。
- 新规则：
  1. 价格、百分比、日期、时间、周期、金额、倍数、得分、样本数和版本号统一使用
     阿拉伯数字与常规单位；
  2. 中文数字只允许出现在“第四浪”“丙二反弹”等固定结构名称中；
  3. 情景路径、收盘判定、目标、失效条件、证据表和审计表同样适用；
  4. “下一交易日”“下一次复查”等导航表达保持中文语义，不做机械数字替换；
  5. 门禁扫描中文数量表达并拒绝用中文数字替代交易数据。
- 适用范围：所有面向用户的盘前、盘中、盘后、历史回放报告和审计附录。
- 验证方式：新增中文数字检测测试；将 2026-09-22 回放的价格、涨跌幅、日期、
  周期和金额全部改为阿拉伯数字后重新预检、冻结和终检。

### 2026-10-25.6｜执行先验优先级、三值证据与动作条件拆分

- 触发案例（仅溯源）：全技能复审发现，盘前高风险先验可能被普通快照降为正常；
  动作确认条件实际描述解除动作，动作失效条件却描述防守继续；中文状态使用全局
  同义词表导致字段间歧义；盘前检查把缺失数据与明确不成立混在一起。
- 新规则：
  1. 盘前 `risk_zone_euphoria` 建立后，普通、观察或未知快照不能解除防守；
     只有压力接受且参与度确认才能恢复进攻，压力拒绝且参与度背离会加强防守。
  2. 动作理由拆为 `action_maintenance` 与 `action_invalidation`；后者只能包含
     推翻当前动作的证据，删除含糊的 `action_confirmation`。
  3. 中文执行覆盖表必须列出防守触发、恢复进攻触发和覆盖失效；操作建议理由必须
     列出动作维持条件和动作解除条件，门禁检查这些内容而非只检查标题。
  4. 中文状态翻译按字段执行，不再使用全局同义词表。
  5. 盘前六项检查使用成立、不成立、未知三值；未知不计入得分，至少四项已知才可
     分类，未知项同时进入数据缺口。
- 适用范围：所有盘前、盘中、盘后和历史回放输出。
- 验证方式：新增普通快照不能解除盘前防守、三值未知不计分、动作维持与解除分离、
  中文按字段翻译和报告触发内容缺失失败测试；重新生成 2026-09-22 回放并完成
  预检、冻结、终检与独立评分。
