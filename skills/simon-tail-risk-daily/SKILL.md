# Simon 每日尾部风险检查

只运行已验证的日线引擎，不执行一年回测、参数优化或盘中 Kill Switch 模拟。

## 执行

1. 在 commentary 中说明本 skill 将增量补数并检查最新完整交易日。
2. 默认运行：

```bash
python3 /Users/a/.codex/skills/simon-tail-risk-daily/scripts/run_daily.py
```

入口会先从 KhQuant 的 Tushare 配置读取凭据并增量刷新数据；Tushare
失败时，固定组合和标准指数可回退到已配置的同花顺金融数据服务。新增的
固定组合/交易所指数日线同时写入 KhQuant 的 DarkDB（`duckdb_data_path`
对应的数据目录）。六因子引擎只读取同一事务提交的
`/Users/a/khquant/data/simon_tail_risk_inputs.duckdb` 快照，避免从多个单证券
文件读到不同截止日。完整市场广度仍以 Tushare 的逐交易日 `daily` 为主，
因为同花顺历史接口是单标的接口。

首次运行时，仓库中的一年 CSV 仅用于初始化这个 DuckDB 快照；之后不再读取或
更新日报 CSV。CSV 只保留为迁移材料和最终信号报告输出。快照包含
`market`、`indices`、`industries`、`portfolio`、`weights`、`external` 六张输入表，
带主键覆盖、事务提交、行数和日期范围审计。

3. 用户指定日期时传入 `--date YYYY-MM-DD`。只有用户明确要求离线或网络不可用时才加 `--no-refresh`；此时必须显著说明数据截止日。
4. 保留脚本的原始结论，不凭主观判断改分。若需解释公式，读取 [model-definition.md](references/model-definition.md)。

## 输出要求

向用户报告：

- 实际信号日和数据截止日；不要把自然日误称为交易日。
- 总分、风险状态和 `Fragility → Deterioration → Shock` 风险链。
- 六个因子逐项触发状态及关键数值证据。
- `波动率目标仓位 × 状态乘数 = 次日开盘目标总仓位`。
- 明确仓位在下一 A 股交易日开盘执行，仍承担隔夜跳空。
- 明确这是日线版本，不含 9:25–9:35 候选池 Kill Switch。

不要只说“触发/未触发”；每项至少给出一个阈值附近的观测值。拥挤脆弱处于 7 日黄灯延续期时，区分“当日原始触发”和“黄灯仍有效”。海外冲击必须同时陈述海外跌幅和国内高 Beta 五日相对强弱。

## 数据失败

若补数失败，先重试一次。仍失败时不要把缺数解释为 0 分或未触发；改用 `--no-refresh` 只生成缓存日报，并在答案开头标明“缓存结果”及所有数据截止日。若脚本没有完整信号，直接报告缺失的数据类别。

## 固定边界

- 组合：`300308.SZ`、`002384.SZ`、`600183.SH`、`300209.SZ`、`600487.SH`，等权收益用于 20 日实现波动率。
- 信号：T 日收盘计算，T+1 日开盘调仓。
- 外围：次晨报告使用不晚于 A 股信号日、且已经完整收盘的最近 IXIC/SOX 交易日；同日期美股收盘可纳入。
- 原文只明确 0/1、3、6 分的部分仓位映射；2/4/5 分为公开标注的插值，不宣称作者精确参数。
